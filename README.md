# sezz.dev

Source for [sezz.dev](https://sezz.dev): engineering portfolio, research journal and technical writing
of Semih Buğra Sezer. Static site built with [Astro](https://astro.build), deployed on Netlify.

## Develop

Requires Node.js ≥ 22.23.4.

```bash
npm ci
npm run dev        # http://localhost:4321
npm run build      # type-check, build, search index, site checks
npm run preview
```

`npm run build` runs, in order:

1. `astro check` — TypeScript and content-schema validation.
2. `astro build` — static output in `dist/`.
3. `pagefind --site dist` — static search index for `/search/`.
4. `scripts/check-site.mjs` — fails if any URL from the previous MkDocs site is neither served nor
   redirected, if any internal link or asset is broken, or if a page loads a third-party script.

## Content

| Collection | Folder | URL |
| --- | --- | --- |
| Projects / case studies | `src/content/projects/` | `/projects/<file>/` |
| Research journal | `src/content/research/` | `/research/<file>/` |
| Writing | `src/content/writing/` | `/<slug>/` (from front matter) |

Schemas live in `src/content.config.ts`; the build fails on invalid front matter.

### Publishing a post

Create `src/content/writing/<name>.md`:

```yaml
---
title: 'Post title'
description: 'One or two sentences shown in listings and previews.'
slug: post-title            # public URL; never change after publishing
created: 2026-11-01
topic: Backend Engineering  # see the enum in content.config.ts
kind: article               # or learning-note (then add `source: { name, url }`)
tags: [go, postgres]
draft: false
---
```

### Adding a research entry

Use `type` (Architecture Study, Research Experiment, Engineering Note, Build Log) and `status`
(Hypothesis, In progress, Observation, Concluded) honestly. Sections: question, background, method,
implementation, observations, evidence, limitations, next steps, references. Keep unverified drafts
at `draft: true`; drafts are not built.

### Project facts

Numbers on project pages carry a `measured` date and must be traceable to the public repository.
Do not publish user, revenue or performance figures that have not been measured.

### Diagrams

Use fenced ` ```mermaid ` blocks. Mermaid is bundled locally and loaded only on pages that contain
a diagram; the source stays readable in a collapsible block.

## Languages

English is served at the site root; Turkish under `/tr/`, German under `/de/`.

- Translated pages (home, AI engineering, projects, research, writing, about, now, contact, search) live in
  `src/views/`. Each view holds its copy as `{ en, tr, de }` and reads the language from the URL. English
  routes are in `src/pages/`; `src/pages/[lang]/[...page].astro` renders the TR/DE versions.
- Shared UI strings (navigation, labels) are in `src/lib/i18n.ts`, together with `TRANSLATED_PAGES`.
- Project cards take `l10n.tr` / `l10n.de` (summary, problem, status) from front matter; the schema requires both.
- Case studies, research entries and articles are English-only. On TR/DE pages they carry an “EN” marker and
  the language switcher leads to that section's translated index.
- Adding a translated page: add its path to `TRANSLATED_PAGES`, create the view, an English route and an entry in
  `[...page].astro`. `check-site` verifies `hreflang` targets and that `<html lang>` matches the URL.

## URLs and redirects

Writing keeps the root-level URLs generated by the old MkDocs Material blog. Old listing routes
(`/archive/*`, `/category/*`, `/page/*`, `/tags/`) redirect to `/writing/` via `netlify.toml`. RSS feeds
stay at `/feed_rss_created.xml` and `/feed_rss_updated.xml`.
